# G1 — Connecteur distant officiel et annuaires

Spec pour un agent de code. Lire d'abord `docs/specs/README.md` § 2 (règles communes), `docs/OAUTH.md`, `docs/SECURITY.md` § 2 et § 10, `docs/research/mcp-apps.md` § 7 à 9. Module Go `github.com/ArseneGA/BAMBULAB-MCP`, Go ≥ 1.26, SQLite pur Go, `CGO_ENABLED=0`.

## 1. Objectif et valeur

Rendre Printalk **joignable et présentable comme connecteur distant** : une URL publique HTTPS (`https://<nom>/mcp`) qui s'ajoute dans claude.ai, Claude Desktop et le mobile, avec une surface publique minimale et sûre, une identité propre (nom Printalk, icône, politique de confidentialité, page d'accueil publique), un outil de diagnostic, et un dossier de **démarches** pour les annuaires (annuaire des connecteurs Claude, registre MCP officiel, mcpservers.org, Glama). Le connecteur distant débloque aussi les **cartes** (vues MCP App : confirmation, aperçu, progression) et l'usage depuis le **mobile**, que `mcp-remote` ne garantit pas (`docs/research/mcp-apps.md` § 7-8).
Segment : tous (porte d'entrée de la distribution). Ce chantier mélange du **code** (petit) et des **démarches** (surtout humaines : soumissions, captures d'écran, compte de test) ; l'agent de code livre le code, les textes et les listes de contrôle, pas les soumissions.

## 2. Périmètre / hors périmètre

Dans le périmètre :
- surface publique dédiée et restreinte (écouteur séparé ou mode « surface publique ») ;
- pages publiques : accueil (`/about`), confidentialité (`/privacy`), assistance (`/support`), icônes ;
- identité du serveur MCP (titre, site, icônes, instructions) alignée sur Printalk ;
- commande de diagnostic `bambud doctor connector` (vérifie une URL publique de bout en bout) ;
- test de conformité des outils (annotations, titres, noms) exigé par les annuaires ;
- manifestes d'annuaire (registre MCP `server.json`, `glama.json`, éventuel `manifest.json` d'extension de bureau) ;
- dossier `docs/DISTRIBUTION.md` : check-lists des démarches, textes FR/EN prêts à coller, matrice « surface × fonction » des vues MCP App avec procédure de preuve.

Hors périmètre : héberger l'instance (SaaS, `docs/strategie/PLAN-SAAS.md`), multi-locataire, facturation, CIMD (client_id par URL), révocation RFC 7009, passkey/WebAuthn, toute soumission effective (humaine), tout compte créé à la place de l'utilisateur, toute modification de la sémantique d'approbation.

## 4. Exigences fonctionnelles

**F1 — Surface publique restreinte.** Nouvel indicateur `--public-listen <adresse>` (env `BAMBU_PUBLIC_LISTEN`, vide par défaut = comportement actuel inchangé). Quand il est fourni, `bambud` ouvre **un second écouteur HTTP** dont le routeur n'expose que cette liste blanche exacte : `POST|GET|DELETE /mcp`, `GET /.well-known/oauth-protected-resource[/mcp]`, `GET /.well-known/oauth-authorization-server`, `POST /oauth/register`, `GET /oauth/authorize`, `GET|POST /oauth/consent/{id}`, `POST /oauth/token`, `GET /about`, `GET /privacy`, `GET /support`, `GET /icon.svg`, `GET /icon-512.png`, `GET /robots.txt`, `GET /health` (version **réduite** : `{"status":"ok"}`, sans chemins, ni version détaillée, ni `mcp_app_views`). Tout le reste (y compris `/confirm/*`, `/stop/*`, `/setup/*` — dont `/setup/printer/{id}` et `/setup/passkeys*` —, `/enroll*`, `/api/*`, `/agent/*` — **v1 et v2** —, la SPA) répond **404** sur cet écouteur (pas 401, pour ne rien révéler). L'écouteur principal est inchangé. Les mêmes gardes (Origin, hôtes autorisés, limiteurs) s'appliquent. Les pages `/oauth/consent/*` restent protégées par le cookie d'un navigateur enregistré (comportement existant). Documenter : le Funnel ou le reverse proxy pointe **uniquement** sur cet écouteur.
**F2 — Limitation de débit sur la surface publique.** Sur l'écouteur public : limite par adresse (en respectant `TrustedProxies`/`X-Forwarded-For` déjà gérés par `guard.go`) pour `POST /oauth/register` (ex. 10/h/IP), `POST /oauth/token` (ex. 60/min/IP), `/mcp` non authentifié (ex. 60/min/IP) ; dépassement → 429 avec `Retry-After`. Valeurs par défaut **bornées et configurables** (`--public-rate-limit`), journalisées sans donnée personnelle. Vérifier d'abord ce que `internal/httpapi` limite déjà (ne pas doubler).
**F3 — Pages publiques.** `GET /about` : page HTML statique (embarquée, **sans JavaScript tiers, sans police ni image externe**) : nom Printalk + baseline (`TAGLINE`), ce que fait le connecteur, ce qu'il ne fait jamais (« vous seul appuyez sur Lancer »), liste des permissions demandées (portée unique `mcp`), mention « compatible imprimantes Bambu Lab (marque appartenant à ses titulaires ; ce logiciel n'est pas affilié) », licence AGPL-3.0, lien dépôt, lien assistance. `GET /privacy` : politique de confidentialité en **français et anglais** : quelles données le serveur traite (fichiers 3D, journal d'impression, réglages, photos de caméra si activée), **où** (sur l'instance de l'utilisateur, aucun envoi à Printalk ni à un tiers autre que le client MCP qui appelle), rétention, comment tout supprimer (`bambud` + corbeille, `bambud oauth --revoke-all`), absence de pistage, contact (variable `BAMBU_CONTACT_EMAIL`, **jamais** une adresse codée en dur ; page « contact non configuré » sinon). `GET /support` : comment signaler un problème, lien `docs/UTILISATION.md`. Texte FR par défaut, `?lang=en` pour l'anglais. Le contenu est stocké dans `internal/httpapi/public/` (modèles `html/template` + `embed`), **testé** (voir CA). Les textes juridiques sont un **projet à faire relire** par l'utilisateur (le dire en tête de `docs/DISTRIBUTION.md`).
**F4 — Icônes publiques.** `GET /icon.svg` = `docs/logo/atelier-icon.svg` (copie versionnée dans `internal/httpapi/public/`), `GET /icon-512.png` = `docs/logo/atelier-icon-512.png`, en-têtes de cache (`public, max-age=86400`), `Content-Type` exact, `X-Content-Type-Options: nosniff`.
**F5 — Identité du serveur MCP.** `mcp.Implementation` : `Title: "Printalk"` (lu de `PRODUCT_NAME` côté Go : créer une constante Go `ProductName` dans `internal/core` alimentée par la même valeur que `web/src/brand.ts`, avec un test qui compare les deux fichiers), `Name` **inchangé** (`bambu-mcp`, pour ne pas casser les configurations existantes), `Version` inchangée, et — **si le SDK `go-sdk v1.8.0` expose `WebsiteURL` et `Icons` sur `Implementation`** (vérifier dans le code du module) — l'URL de `/about` et l'icône (URL absolue construite depuis `PublicURL`, sinon omises). Les `Instructions` conservent tout leur contenu de sécurité actuel ; seule la première phrase passe de « Atelier 3D pour imprimantes Bambu Lab » à « Printalk, atelier 3D pour imprimantes Bambu Lab ». Test : le texte des instructions contient toujours les phrases sur `request_print_confirmation`, `cancel_print` et « Ne demande JAMAIS … code de lancement ».
**F6 — Conformité des outils (annotations).** Test `TestEveryToolHasTitleAnnotationsAndSafeHints` : pour chaque outil de `tools/list` : `Title` non vide, `Annotations` non nul avec **les trois indications** `readOnlyHint`, `destructiveHint`, `idempotentHint` renseignées explicitement (ou la combinaison par défaut du SDK documentée), `openWorldHint` vrai uniquement pour les outils qui sortent vers Internet (`import_from_url`), description ≤ 2 000 caractères (borne à vérifier auprès des annuaires, à vérifier), nom ≤ 64 caractères `[a-zA-Z0-9_-]`. Un outil **en écriture** (`upload_print_artifact`, `cancel_job`…) ne doit pas déclarer `readOnlyHint=true`. Corriger les annotations manquantes **sans changer le comportement ni le nom** d'aucun outil.
**F7 — `bambud doctor connector --url https://<nom>`.** Sous-commande de diagnostic (aucune écriture de données) qui, **depuis l'extérieur**, vérifie : (1) TLS valide (chaîne, nom, expiration) ; (2) `POST /mcp` sans jeton → **401** avec `WWW-Authenticate` portant `resource_metadata` ; (3) `GET /.well-known/oauth-protected-resource` → JSON avec `resource` = URL `/mcp` et `authorization_servers` ; (4) `GET /.well-known/oauth-authorization-server` → `authorization_endpoint`, `token_endpoint`, `registration_endpoint`, `code_challenge_methods_supported` contenant `S256` ; (5) DCR : `POST /oauth/register` d'un client public de test avec `redirect_uris:["https://claude.ai/api/mcp/auth_callback"]` → `client_id` (le client de test est purgé automatiquement : comportement existant à une heure) ; (6) `GET /oauth/authorize` d'un client inconnu → page d'erreur, **jamais une redirection** ; (7) **chemins interdits** : `GET /confirm/x`, `/stop/x`, `/setup/launch-code`, `/setup/passkeys`, `/setup/printer/x`, `/enroll`, `/api/capabilities`, `/agent/v1/tasks/next`, `/agent/v2/…` doivent répondre 404 (surface publique) ; (8) `/about`, `/privacy`, `/icon.svg` répondent 200 ; (9) avec `--token <bearer>` (ou variable `BAMBU_API_TOKEN`, **jamais** affichée), `initialize` MCP puis `tools/list` : nombre d'outils, présence de `_meta.ui.resourceUri` sur `request_print_confirmation`, `ressources/read ui://bambu/print-confirm.html` non vide et de type `text/html;profile=mcp-app`. Sortie : tableau OK/KO/AVERTISSEMENT en français, code de sortie ≠ 0 si un point bloquant échoue, option `--json`. Le jeton n'apparaît jamais dans la sortie.
**F8 — Manifestes d'annuaire (fichiers, pas soumissions).** Créer, à la racine ou dans `docs/distribution/`, avec en-tête « à vérifier avant soumission » : `server.json` (registre MCP officiel ; schéma à lire sur le dépôt du registre, à vérifier ; description, dépôt, version, `packages`/`remotes` — **attention : une instance auto-hébergée n'a pas d'URL fixe**, ne pas inventer d'URL ; décrire le paquet local `bambu-mcp` (pont stdio) et laisser `remotes` vide ou renseigné par l'utilisateur), `glama.json` (revendication du dépôt, à vérifier), et, **seulement si** la spécification de l'extension de bureau est lisible et stable (à vérifier), un `manifest.json` de paquet d'extension pour Claude Desktop lançant le pont `bambu-mcp`. Chaque fichier est validé par un test qui vérifie au moins qu'il est du JSON valide, que le nom/la description/la version correspondent à `core.Version`, et qu'il ne contient **aucun secret ni chemin local**.
**F9 — Dossier de démarches `docs/DISTRIBUTION.md`.** (a) *Pré-requis communs* : instance publique en https (URL fixe et durable), page `/privacy`, compte de test, 3 à 5 captures, description courte (≤ 150 caractères) et longue, catégorie, licence, contact. (b) *Fiche par annuaire* (tableau : annuaire, qui soumet, formulaire/lien **à vérifier**, pré-requis, statut `à faire`, date, preuve) pour : **annuaire des connecteurs Claude** (exigences d'Anthropic **à vérifier** : l'agent doit chercher la page officielle « connectors directory submission » sur `claude.com`/`support.claude.com`, la lire, citer l'URL et la date, et lister chaque exigence trouvée dans un tableau « exigence / satisfaite par / reste à faire » ; s'il ne peut pas la lire, écrire « **exigences non lues — à vérifier** » et ne rien présumer), **registre MCP officiel** (CLI `mcp-publisher`, espace de noms `io.github.<compte>/…` ou domaine, à vérifier), **mcpservers.org** (formulaire de soumission, à vérifier), **Glama** (indexation du dépôt, revendication, à vérifier), éventuellement PulseMCP/Smithery (à vérifier). (c) *Question de fond à trancher par l'utilisateur* (voir § 10) : un connecteur d'annuaire suppose normalement une URL **gérée par l'éditeur** ; une instance auto-hébergée par client n'en a pas. (f) *Exposition* : Tailscale Funnel (ports et limites autorisés **à vérifier** sur la documentation Tailscale ; commande exacte vers l'écouteur public), alternative reverse proxy (Caddy) + nom de domaine, alternative tunnel Cloudflare (à vérifier), avec pour chacune : qui voit quoi, ce qui est exposé (F1), comment révoquer.

## 6. Sécurité et règles non négociables

- La surface publique **ne sert jamais** `/confirm`, `/stop`, `/setup`, `/enroll`, `/api/*`, `/agent/*` ni la SPA ; test automatisé de cette liste blanche (négative : tout chemin hors liste → 404).
- Le jeton OAuth reste accepté **seulement** sur `/mcp` ; il ne peut ni approuver un lancement ni un arrêt (`TestNoMCPToolCanApproveAConfirmation` doit rester vert ; ajouter le même contrôle via l'écouteur public).
- Aucun secret dans `/about`, `/privacy`, `server.json`, `glama.json`, la sortie de `doctor`, les journaux. Le contact vient d'une variable d'environnement.
- Le diagnostic n'envoie le jeton qu'à l'URL fournie par l'humain et jamais ailleurs ; il refuse les URL non `https` sauf `--allow-http` (boucle locale seulement).
- Redirections OAuth : liste blanche inchangée (callbacks de Claude + boucle locale + `--oauth-redirects`) ; ne pas ajouter d'hôte par défaut (G8 documente les autres clients).
- Les textes juridiques sont des projets : ne pas affirmer de conformité (RGPD, etc.) que le code ne démontre pas.
- Un annuaire n'est jamais soumis par l'agent de code ; aucune création de compte.

## 7. Compatibilité production

- Sans `--public-listen`, **rien ne change** : même écouteur, mêmes routes, même `/health`. Le Bearer statique, `mcp-remote --header`, le pont `bambu-mcp`, Claude Code fonctionnent comme avant.
- `Name: "bambu-mcp"` est conservé ; seule la propriété `Title` change (affichage) : Claude Desktop via `mcp-remote` reste configuré par sa clé de configuration locale, pas par ce titre.
- Aucun outil renommé ou supprimé ; `TestToolsListConformsToMCPSpec` vert ; les annotations corrigées (F6) ne changent pas les comportements.
- Pas de migration ; la base existante n'est pas touchée.
- Les pages `/about` et `/privacy` sont aussi servies sur l'écouteur principal (lecture seule, publiques) : vérifier que `guard.go` ne les prend pas pour des chemins humains.

## 8. Critères d'acceptation (CA)

Tests Go dans `internal/httpapi/public_test.go`, `cmd/bambud/doctor_test.go`, `internal/mcpserver/annotations_test.go`, `internal/mcpserver/identity_test.go`. Le service de test se démarre comme dans `internal/httpapi/oauth_test.go` (service en mémoire) ; le simulateur d'imprimante (`internal/printer/sim`) sert pour `request_print_confirmation` dans CA9.
- **CA1** Étant donné `--public-listen` actif, quand on appelle sur l'écouteur public chacun de ces chemins : `/confirm/abc`, `/stop/abc`, `/setup/launch-code`, `/enroll`, `/api/capabilities`, `/api/jobs/x`, `/agent/v1/tasks/next`, `/`, `/assets/x.js`, alors la réponse est **404** (table de cas complète) ; et `/mcp` sans jeton répond 401 avec `resource_metadata`.
- **CA2** Étant donné l'écouteur public, quand on parcourt un flux OAuth complet de test (découverte, DCR, autorisation avec un cookie de navigateur enregistré, échange de jeton), alors un jeton est obtenu et `tools/list` fonctionne ; avec ce jeton, `GET /api/capabilities` sur l'écouteur **principal** répond 401 (jeton non valable hors `/mcp`).
- **CA3** Étant donné 70 appels rapprochés à `POST /oauth/token` depuis la même IP, alors les appels au-delà de la limite répondent 429 avec `Retry-After`, et un appel d'une autre IP passe.
- **CA4** `/about`, `/privacy`, `/support` répondent 200, `Content-Type: text/html; charset=utf-8`, contiennent « Printalk », ne contiennent **aucune** référence à un hôte externe (`http://`/`https://` autre que le dépôt et la documentation citée, aucun `<script src>`), et `/privacy?lang=en` renvoie le texte anglais ; `/privacy` sans `BAMBU_CONTACT_EMAIL` affiche « contact non configuré » (aucune adresse par défaut).
- **CA5** `/icon.svg` et `/icon-512.png` ont les octets de `docs/logo/*` (comparaison de sha256) et les bons types MIME.
- **CA6** `initialize` renvoie `serverInfo.title == "Printalk"` et `name == "bambu-mcp"` ; les instructions contiennent encore les trois phrases de sécurité.
- **CA7** `TestEveryToolHasTitleAnnotationsAndSafeHints` passe sur la liste réelle des outils ; un test négatif prouve qu'il échoue si un outil sans titre est ajouté.
- **CA8** `bambud doctor connector --url <serveur de test httptest TLS>` : tableau tout OK sur un serveur conforme ; avec une surface mal configurée (un `/confirm/x` servi en 200), le diagnostic sort en code ≠ 0 avec la ligne « chemin interdit exposé » ; la sortie ne contient jamais la valeur du jeton passé en `--token` (test de recherche de sous-chaîne).
- **CA9** Via le client MCP du SDK connecté à l'écouteur public, `request_print_confirmation` (imprimante simulée) renvoie un résultat portant `_meta.ui.resourceUri` ; `resources/read ui://bambu/print-confirm.html` rend du HTML non vide au type `text/html;profile=mcp-app` ; **aucun** appel d'outil ne produit un lancement (`TestNoMCPToolCanApproveAConfirmation` étendu à cet écouteur).
- **CA10** `server.json` et `glama.json` sont du JSON valide, cohérents avec `core.Version`, sans secret (test d'expressions régulières sur chemins `C:\`, `/home/`, jetons `bat_`, `Bearer`).
- **CA11** `TestProductNameMatchesBrandTS` : la constante Go et `web/src/brand.ts` portent le même nom.
- **CA12** Sans `--public-listen`, la suite complète existante (`go test -short ./...`) passe sans modification de test hors ajouts.
- **Preuve manuelle (non automatisable, à fournir par l'humain, consignée dans `docs/DISTRIBUTION.md`)** : matrice « surface × fonction » remplie pour au moins Claude Desktop (connecteur distant) et claude.ai ; l'agent de code ne peut pas la remplir et ne doit **pas** inscrire « OK » sans capture.

## 10. Risques, questions ouvertes, taille

Taille : **M** (code S ≈ 2 jours ; démarches et preuves M, dépendent de l'humain).

Risques : texte juridique inexact (relecture humaine obligatoire) ; exigences d'annuaire inconnues (non lues) ; Funnel jamais testé en vrai ; une page d'accueil publique expose l'existence du service (acceptable, il faut une URL de toute façon) ; surface exposée à Internet = surface d'attaque (limiteurs, liste blanche, tests).

2. **Marque dans l'identité MCP** : passer `Title` à « Printalk » (recommandé, `Name` inchangé) ou garder « Atelier Bambu Lab » jusqu'à la décision définitive du nom (le nom est « provisoire » dans `brand.ts`) ? Un renommage du `Name` casserait les configurations existantes : à éviter.
