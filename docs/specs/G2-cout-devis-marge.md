# G2 — Coût réel, devis et marge

Spec pour un agent de code. Lire d'abord `docs/specs/README.md` § 2 (règles communes), `docs/UTILISATION.md` § 11 (coût, journal, tableau de bord), `docs/strategie/ETUDE-MARCHE.md` §§ 3.3, 6, 7. Module Go `github.com/ArseneGA/BAMBULAB-MCP`, Go ≥ 1.26, SQLite pur Go, `CGO_ENABLED=0`.

## 1. Objectif et valeur

Répondre à la question que se posent les vendeurs et les petites fermes : « **combien me coûte vraiment cette pièce, à quel prix la vendre, et qu'est-ce qui me reste après les frais de la plateforme ?** » : prix de revient par pièce et par commande (matière, énergie, usure, temps de préparation et de finition, consommables, provision pour les échecs), prix de vente conseillé selon la marge cible, frais de plateforme paramétrables (Etsy, MakerWorld, vente directe), et **devis PDF** généré par le serveur. C'est le seul argument que les vendeurs paient tout de suite (ROI chiffrable en quelques ventes, `ETUDE-MARCHE.md` § 1 point 3).
Segment : vendeurs Etsy/MakerWorld/Printables (1 à 3 imprimantes), petites fermes (3 à 15).

## 2. Périmètre / hors périmètre

Dans le périmètre : réglages de tarification ; calcul du prix de revient d'une pièce à partir d'une impression découpée, d'un plan saisi ou de l'historique du journal ; prix conseillé avec frais de plateforme ; devis (créer, modifier, envoyer, accepter/refuser, expirer) ; PDF du devis côté serveur ; socle `internal/pdfdoc` réutilisé par G4 ; outils MCP, routes HTTP, écrans web.
Hors périmètre : **facturation** légale (numérotation fiscale, TVA par pays, mentions légales : le devis porte la mention « ceci n'est pas une facture » et ne donne aucun conseil fiscal) ; connexion aux API Etsy/MakerWorld ; paiement en ligne ; calcul des frais de port (le port est une ligne libre du devis) ; gestion des commandes et de leur traçabilité (c'est **G5** : une commande peut être créée à partir d'un devis accepté, mais cette liaison est faite par G5) ; multi-devises avec taux de change.
Frontière avec G5 : G2 possède `quotes`/`quote_lines` et les fonctions de prix ; G5 possède `orders` et le rapprochement commande ↔ impressions. Le « coût par commande » de G2 est le coût **prévisionnel du devis** ; le coût **réel** d'une commande (somme des impressions liées) est calculé par G5 en réutilisant les fonctions de G2/`insights`.

## 3. État actuel dans le code

## 4. Exigences fonctionnelles

**F1 — Réglages de tarification (`pricing`).** Nouveau document de réglages stocké dans `insight_settings` (clé `pricing`, pas de migration) : `labor_rate_per_hour` (taux horaire, défaut 0), `default_prep_minutes` (préparation, défaut 0), `default_finish_minutes` (finition/post-traitement, défaut 0), `consumables_per_item` (emballage, colle, étiquette ; défaut 0), `failure_rate` (taux d'échec attendu, 0 ≤ f < 0,5, défaut 0), `target_margin` (fraction, 0 ≤ m < 1, défaut 0,40, **valeur de départ indicative**), `margin_mode` (`marge` = part du prix de vente | `coefficient`), `markup_coefficient` (si mode coefficient, ≥ 1), `rounding` (`none` | `0.05` | `0.10` | `1`, arrondi **au-dessus** seulement), `vat_rate` (défaut 0), `price_display` (`ht` | `ttc`, défaut `ht`), `default_platform` (id d'un préréglage), et `fee_presets[]` (voir F2). Chaque champ a une borne, un défaut et une phrase d'aide ; valeurs hors bornes → erreur claire. Le document ne contient aucun secret.
**F2 — Préréglages de frais de plateforme (paramétrables, jamais figés).** Structure `FeePreset{id, label, percent (fraction du prix de l'article), fixed_per_sale, listing_fee, payment_percent, payment_fixed, applies_to_shipping (bool), verified (bool), source_url, checked_at, note}`. **Préréglages fournis** : `etsy`, `makerworld`, `direct`. **Règle** : les taux ne sont **pas** écrits en dur sauf s'ils sont vérifiés sur la page officielle de la plateforme au moment du codage (URL + date dans `source_url`/`checked_at` ; sinon **tous les montants valent 0 et `verified=false`**). Un préréglage non vérifié ou à zéro doit produire dans **toute** sortie de prix l'avertissement « Frais de la plateforme X non renseignés ou non vérifiés : à vérifier sur la page officielle ; le prix conseillé ci-dessous ne tient pas compte de frais réels. » et le champ `fees_verified:false`. Valeur par défaut `direct` : aucun frais de plateforme (les frais de paiement sont à saisir). La structure de frais de MakerWorld n'a **pas** été vérifiée par les auteurs de cette spec : l'agent ne doit rien affirmer à son sujet sans source (à vérifier). L'utilisateur peut créer/modifier/supprimer ses préréglages (`set_pricing_settings`).
**F3 — Prix de revient d'une pièce.** Fonction pure `insights.CostPrice(in CostPriceInput, set Settings, pr PricingSettings) CostPriceResult` : coût d'impression `C_print` = total de `compute()` (matière + énergie + usure, **inchangé**) ; coût effectif par pièce bonne `C_print_eff = C_print / (1 − f)` (chaque pièce bonne demande 1/(1−f) tentatives en moyenne) ; main-d'œuvre `L = (prep + finish)/60 × labor_rate` (minutes saisies ou valeurs par défaut) ; consommables `K` ; **coût de revient unitaire** `C = C_print_eff + L + K`. Le résultat détaille chaque terme avec son **niveau** (matière/durée : *mesuré par le slicer* si l'archive découpée est disponible, sinon *estimé* ; énergie/usure : *calculé*, prix : *réglage utilisateur* ou *indicatif* ; taux d'échec : *réglage* ou *observé*). Les `assumptions[]` listent tout ce qui est par défaut.
**F4 — Taux d'échec observé (facultatif, honnête).** Si `model_id` est donné et que le journal contient **n ≥ 5** impressions terminées de ce modèle (`print_logs.model_id`), `CostPrice` expose `observed_failure_rate = (failed + cancelled)/n` avec `n` et le niveau « mesuré (journal) », et l'utilise **seulement si** l'option `use_observed_failure_rate` est vraie ; sinon il l'indique en information. Avec n < 5 : « échantillon trop petit, taux non utilisé ».
**F5 — Prix de vente conseillé.** Fonction pure `insights.SuggestPrice`. Mode `marge` : `P = (C + F_unit) / (1 − p − m)` avec `p = percent + payment_percent` (fractions), `F_unit = (fixed_per_sale + payment_fixed + listing_fee) / q` (q = quantité de la commande), `m = target_margin` ; refuser avec un message explicite si `1 − p − m ≤ 0` (« frais + marge ≥ 100 % : marge cible impossible »). Mode `coefficient` : `P = C × coefficient` (les frais sont alors **déduits** pour afficher la marge nette obtenue). Arrondi `rounding` toujours **vers le haut** (jamais sous la marge visée). Affichage : `price_display = ttc` ⇒ `P_ttc = P × (1 + vat_rate)` (affichage seulement, aucun conseil fiscal). Sortie : décomposition complète (coût de revient, frais en montants, marge nette en montant et en %, prix HT/TTC, prix pour q pièces), `fees_verified`, avertissements, et une « marge nette réellement obtenue » recalculée après arrondi. Exemple de contrôle numérique (préréglage de test fictif, jamais livré) : `C = 5,00`, `fixed_per_sale = 0,30`, `percent = 0,10`, `q = 1`, `m = 0,40` ⇒ `P = 10,60` ; profit = `10,60 × 0,90 − 0,30 − 5,00 = 4,24 = 0,40 × 10,60`.
**F6 — Entrées du calcul.** Trois façons de fournir la matière et la durée, par ordre de préférence : (1) `print_job_id` (archive découpée : masses par emplacement et durée lues par `insights` comme dans `planFromJob`) ; (2) `model_id` : l'impression la plus récente **réussie** et découpée pour ce modèle (journal ou expérience) ; si aucune, erreur guidant vers `execute_headless_slice` (le calcul **ne découpe jamais** de lui-même) ; (3) plan saisi (`printer_model`, `duration_minutes`, `filaments[]`, comme `estimate_cost`). Plusieurs pièces sur un plateau : `parts_per_plate` divise le coût d'impression de la plaque (nombre saisi, sinon 1).
**F7 — Devis.** Un devis = en-tête (numéro `D-AAAA-NNNN` séquentiel non réutilisé, état, client, validité en jours, notes, conditions) + lignes (`model_id`/`version_id` facultatifs, description, quantité, coût de revient unitaire figé, prix unitaire, détail du calcul) + totaux HT, TVA, TTC. États : `brouillon` → `envoye` → `accepte` | `refuse` | `expire` (expiration calculée à la lecture). **Un devis `envoye` est figé** : le modifier crée une **révision** (même numéro, `revision+1`), l'ancienne reste consultable. Le prix de chaque ligne peut être **surchargé** à la main (le calcul conseillé reste affiché à côté ; l'écart est tracé). Données client minimales (nom/organisme, adresse facultative, e-mail facultatif) : stockées localement, jamais envoyées à un tiers ; un bouton de suppression des données d'un devis existe.
**F8 — Profil vendeur.** Réglage `seller_profile` (clé dans `insight_settings`) : raison sociale/nom, adresse, identifiant fiscal (texte libre), e-mail, conditions par défaut, logo (blob PNG/JPEG ≤ 512 Kio vérifié par `checkImageBlob`, déjà présent dans `journal.go`). **Tout est facultatif** ; le PDF s'en passe.
**F9 — Socle PDF `internal/pdfdoc` (réutilisé par G4).** Paquet minimal, **pur Go**, déterministe : `pdfdoc.New(opts) *Doc` avec `Title`, `Author`, `CreatedAt` (injecté pour des PDF reproductibles), `Heading(level, text)`, `Paragraph(text)`, `Table(headers, rows, colWidths)`, `KeyValue(rows)`, `Image(pngBytes, widthMM)`, `PageBreak()`, `Footer(text)` (pied de page avec numéro `page n/N` et texte, ex. empreinte), `Attach(name, bytes)` (pièce jointe, utile à G4), `Bytes() ([]byte, error)`. Mise en page A4, marges 15 mm, police de base **intégrée au PDF** compatible français (accents, €, « — ») ; couleurs du vert Printalk pour les titres (`#095a40`) et filets (`#16a06b`), texte noir. **Choix de bibliothèque** (à trancher par l'agent, justification écrite dans `docs/DEVIS.md`) : candidat recommandé `github.com/go-pdf/fpdf` (MIT, successeur maintenu de gofpdf, pur Go, polices cœur + TTF embarquées, pièces jointes) ; alternatives `github.com/signintech/gopdf` (MIT) ou `github.com/johnfercher/maroto/v2` (MIT, au-dessus de fpdf). Pour les **tests seulement** : `github.com/pdfcpu/pdfcpu` (Apache-2.0) pour valider la structure du PDF. **À vérifier par l'agent avant d'ajouter** : licence exacte, version, absence de cgo, taille ajoutée au binaire ; vérifier la compatibilité AGPL-3.0 et noter les trois dans `docs/DEVIS.md` ; ne pas utiliser une bibliothèque archivée (`jung-kurt/gofpdf` est archivée) ni sous licence non libre.
**F10 — PDF du devis.** `quotepdf.Render(q Quote, seller SellerProfile) ([]byte, error)` sur `pdfdoc` : en-tête (logo du vendeur si présent, sinon rien ; « Devis n° … rév. … », date, validité), blocs vendeur/client, tableau des lignes (description, qté, prix unitaire, total), totaux HT/TVA/TTC (la TVA n'apparaît que si `vat_rate > 0`), notes et conditions, mention « Ce document est un devis, pas une facture. », pied de page « Édité avec Printalk » **désactivable** par un réglage (défaut : activé), numéro de page. **Le PDF ne contient pas le coût de revient ni la marge** (informations internes) ; une variante interne `internal=true` (feuille de marge) les montre, clairement titrée « DOCUMENT INTERNE ». Le PDF est stocké comme blob (sha256) et servi par URL signée (même mécanisme que les archives d'export).
**F11 — Outils MCP (nouveaux ; texte rendu au modèle en français).**
- `get_pricing_settings` (lecture) : renvoie F1/F2 + `fees_verified` par préréglage + avertissement si défauts.
- `set_pricing_settings` (écriture, `SettingsPatch` fusionnant les préréglages ; `0`/`null` supprime ; refuse toute valeur hors borne) : texte rendu « Réglages de tarification enregistrés. Préréglages non vérifiés : … ».
- `suggest_price` (lecture) : entrées `print_job_id` | `model_id` | plan saisi, `quantity`, `platform` (id de préréglage), `target_margin`, `prep_minutes`, `finish_minutes`, `parts_per_plate`, `use_observed_failure_rate`. Sortie structurée (F3/F5) + texte : « Coût de revient 5,00 € ; prix conseillé 10,60 € HT (marge nette 40 %, frais Etsy 1,36 €). Sources : matière mesurée (archive), énergie calculée, main-d'œuvre saisie. À vérifier : taux de frais non vérifiés. ». Ne lance ni ne découpe rien.
- `create_quote`, `get_quote`, `list_quotes`, `update_quote` (état, lignes, surcharge de prix, révision), `get_quote_pdf` (renvoie une URL signée de 10 minutes et le sha256 ; paramètre `internal` pour la feuille de marge).
Les outils existants (`estimate_cost`, `get_cost_settings`, `set_cost_settings`, `get_project_costs`…) sont **inchangés**. Chaque nouvel outil a `Title`, `Annotations` correctes (lecture seule vs écriture) et un `outputSchema` d'objet.
**F12 — Routes HTTP.** `GET|PUT /api/pricing/settings` ; `POST /api/pricing/suggest` ; `GET|POST /api/quotes` ; `GET|PATCH|DELETE /api/quotes/{id}` ; `POST /api/quotes/{id}/pdf` (génère et renvoie l'URL signée) ; `GET /api/quotes/{id}/pdf/{sha}.pdf?exp&sig` (signée, ajoutée à `isSignedAsset` de façon aussi étroite que les exports). Protégées par le Bearer comme le reste de `/api/*`.
**F13 — Écrans web (vert Printalk).** Dans « Coûts » (`/couts`, `InsightsPage`) : un onglet **Tarification** (formulaire F1 avec aide, tableau des préréglages de frais avec badge « à vérifier » tant que `verified=false`, simulateur « prix conseillé » avec curseur de marge) ; une page **Devis** (`/devis`) : liste (numéro, client, total, état, validité), détail (lignes éditables, prix conseillé à côté du prix retenu, bouton « Télécharger le PDF », bouton « Marquer comme envoyé/accepté/refusé »), création à partir d'un modèle de la Bibliothèque (bouton « Chiffrer » sur la fiche modèle `Model.tsx`). Lien menu « Devis » sous « Coûts » (`Shell.tsx`). Composants `web/src/components/ui.tsx`, jetons `web/src/design/tokens.css`, textes en français, états vides explicites (« Aucun devis. »), erreurs lisibles.
**F14 — Documentation.** `docs/DEVIS.md` : formules (F3/F5 avec l'exemple chiffré), explication des niveaux (mesuré/calculé/estimé/réglage), tableau des préréglages et de leur statut de vérification (avec URL et date), choix de la bibliothèque PDF (licence, version), limites (pas une facture).

## 6. Sécurité et règles non négociables

- Aucun lancement ni arrêt d'impression n'est touché ; aucun outil nouveau ne peut approuver quoi que ce soit (les tests `TestNoMCPToolCanApproveAConfirmation` restent verts).
- Les données client d'un devis sont des **données personnelles** locales : jamais dans les journaux applicatifs ni les traces, jamais renvoyées par un outil de liste au-delà du nom d'affichage, suppression possible.
- Le PDF servi par URL signée (HMAC, expiration 10 min) ; aucun chemin de fichier du serveur dans le PDF ni dans les réponses ; nom de fichier assaini (`D-2026-0001-rev1.pdf`).
- Mesuré/calculé/estimé distingués dans chaque ligne du calcul et dans le PDF interne ; **aucun taux de frais présenté comme officiel** sans source et date ; les valeurs par défaut sont libellées « indicatif » / « à vérifier ».
- Entrées validées (bornes, NaN/Inf refusés comme `okMoney` dans `settings.go`), arrondis monétaires déterministes (arrondi au centime à l'**affichage et au stockage des totaux**, calculs internes en flottants ; tests sur les cas limites).
- Aucune écriture dans les originaux du catalogue ; un devis référence un `version_id` figé.
- Aucun appel réseau sortant nouveau.

## 7. Compatibilité production

- Les outils, routes et réglages existants de coût sont **inchangés** ; `DefaultSettings()` inchangé ; aucune donnée existante n'est recalculée (la tarification est un calque **par-dessus** le coût existant).
- Tous les défauts de tarification sont neutres : main-d'œuvre 0, consommables 0, échecs 0 ⇒ `C == total estimé existant` à l'arrondi près (test d'équivalence).
- Migration additive uniquement (nouvelles tables) ; aucune colonne existante modifiée.
- Binaire toujours compilable avec `CGO_ENABLED=0` pour Linux et Windows (`make cross`/`go build ./...` avec `GOOS=linux`) après ajout de la bibliothèque PDF.
- `tools/list` : seuls 8 outils ajoutés, noms valides, `TestToolsListConformsToMCPSpec` vert.

## 8. Critères d'acceptation (CA)

Tests Go : `internal/insights/pricing_test.go`, `internal/insights/quote_test.go`, `internal/pdfdoc/pdfdoc_test.go`, `internal/quotepdf/quotepdf_test.go` (ou sous `internal/insights`), `internal/mcpserver/pricing_tools_test.go`, `internal/httpapi/pricing_test.go`. Web : `web/src/api/pricing.test.ts`, tests de pages `web/src/pages/Quotes.test.tsx`. Le simulateur d'imprimante sert à produire une impression **découpée et terminée** pour alimenter le journal (comme `internal/insights/journal_test.go`, `internal/printing/e2e_test.go`).
- **CA1** Étant donné `C = 5,00`, un préréglage de test `percent = 0,10`, `fixed_per_sale = 0,30`, `m = 0,40`, `q = 1`, quand on appelle `SuggestPrice`, alors `P == 10,60` et la marge nette recalculée vaut 40 % ; avec `m = 0,95` et `percent = 0,10`, l'appel échoue avec « marge cible impossible ».
- **CA2** Étant donné `f = 0,2`, `C_print = 4,00`, `L = 1,00`, `K = 0,50`, alors `C = 4,00/0,8 + 1,00 + 0,50 = 6,50` (table de cas, y compris `f = 0` ⇒ égalité avec `estimate_cost`).
- **CA3** Arrondi : `P = 10,61` avec `rounding = 0.10` ⇒ `10,70` (jamais `10,60`) ; `rounding = none` ⇒ inchangé ; la marge nette après arrondi est ≥ la marge cible.
- **CA4** Préréglage `etsy` par défaut : `verified=false`, tous montants 0 ; toute sortie de `suggest_price` avec ce préréglage contient `fees_verified:false` et la phrase d'avertissement ; **aucun** nombre de frais n'apparaît dans le code source sans `source_url` et `checked_at` (test qui lit les préréglages par défaut).
- **CA5** Étant donné une impression simulée terminée et découpée (`print_job_id`), `suggest_price` rend les masses et la durée lues de l'archive avec le niveau « mesuré (slicer) » ; avec un plan saisi, le niveau est « estimé ».
- **CA6** Étant donné 6 impressions du modèle M dans le journal dont 2 `failed`, quand `use_observed_failure_rate=true`, alors `observed_failure_rate = 0,333` avec `n = 6` et il est utilisé ; avec 4 impressions, il n'est pas utilisé et le texte dit « échantillon trop petit ».
- **CA7** Étant donné un modèle sans aucune impression découpée, `suggest_price(model_id)` échoue avec un message qui nomme `execute_headless_slice` et **ne démarre aucune découpe** (compteur de travaux inchangé).
- **CA8** Numérotation : 20 créations de devis concurrentes ⇒ 20 numéros distincts, consécutifs, format `D-AAAA-NNNN` ; passer à l'année suivante repart de `0001`.
- **CA9** Un devis `envoye` refuse une modification directe de ses lignes ; la modification crée la révision 2 (même numéro) ; l'ancienne reste lisible ; l'audit contient les deux évènements.
- **CA10** `get_quote_pdf` renvoie une URL signée qui sert un fichier commençant par `%PDF-` et finissant par `%%EOF`, validé par `pdfcpu` (test seulement) ; l'extraction de texte contient le numéro, le nom du client, les totaux, la mention « pas une facture » et **ne contient pas** « coût de revient » ; la variante `internal=true` le contient et porte « DOCUMENT INTERNE » ; l'URL expirée ou altérée répond 403.
