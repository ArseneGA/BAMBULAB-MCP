# Jalon 9 — sauvegarde, livraison, installation

Date : 2026-11-06. Périmètre : `internal/backup`, `cmd/bambud/backup_cli.go`, `cmd/bambu-mcp` (`--api-token-file`), `internal/core` (`StudioWrapper`, `LockDataDir`), `scripts/release.*`, `scripts/smoke.ps1`, `deploy/`. État et preuves : `docs/ETAT.md`. Usage : `docs/INSTALL.md`.

## Sauvegarde / restauration / vérification

**Format** : archive tar (gzip si `.tar.gz`/`.tgz`, ou `.tar`). `.tar.zst` est refusé avec un message (pas de dépendance zstd embarquée). Contenu, dans cet ordre :

1. `db/bambu.db` — copie cohérente par `VACUUM INTO` sur une **connexion distincte en lecture seule** (le service n'est pas arrêté, SQLite WAL laisse écrire pendant la copie), puis `PRAGMA integrity_check` de la copie ;
2. `blobs/ab/cd/<sha256>` — chaque blob est relu pendant la copie et son empreinte comparée à son nom (un blob corrompu **fait échouer** la sauvegarde plutôt que d'archiver un contenu faux) ;
3. `secrets/master.key`, `secrets/printers.secrets`, `assets.key` (sauf `--exclude-secrets`) ;
4. `manifest.json` **en dernier** : format, date, version, version de schéma, présence des secrets, liste `{path, size, sha256}` de tous les fichiers. Une archive sans manifeste (écriture interrompue) est refusée.

La base est copiée **avant** les blobs : un blob ajouté entre les deux est un orphelin inoffensif, l'ordre inverse pourrait référencer un blob absent. Un fichier `<archive>.sha256` donne l'empreinte de l'archive entière. Écriture en `.part` puis renommage, droits 0600.

**Restauration** : lecture complète de l'archive vers un dossier de travail **dans le dossier cible** (même système de fichiers) avec vérification de chaque fichier contre le manifeste, liste blanche stricte de chemins (aucun lien, aucun `..`, aucun nom hors format), contrôle d'intégrité de la base et de sa version de schéma (refus d'une base plus récente que le binaire), et seulement ensuite mise en place par `rename`. Dossier non vide : refus, sauf `--force` qui **déplace** l'existant dans `.pre-restore-<date>/` (jamais de suppression). `bambud restore` prend le verrou d'instance du dossier : impossible sur le dossier d'un service en marche.

**Vérification** (`bambud verify`) : dossier de données (intégrité, clés étrangères, empreinte de chaque blob — `--quick` saute la relecture —, blobs référencés par `source_files`/`derived_assets`/`experiment_candidates`/`print_previews` présents) ou archive (`--archive` : empreinte globale, manifeste, base, références). Code de sortie 1 en cas d'anomalie ; `--json`.

**Limites** : l'archive n'est pas chiffrée (elle contient le coffre chiffré et sa clé : protéger le support). Sous Windows la clé maître est liée à DPAPI : une archive prise sous Windows ne se relit pas sur un autre compte. Les dossiers `work/`, `agent-inbox/`, `agent-staging/`, `tmp/` et `demo-src/` (reconstructibles) ne sont pas sauvegardés.

## Slicer sous Linux sans écran

`core.Config.StudioWrapper` alimente `slicer.Config.Wrapper`. `bambud --studio-wrapper "xvfb-run -a"` / `BAMBU_STUDIO_WRAPPER` ; `none` désactive. Sans réglage : sous Linux, sans `DISPLAY`/`WAYLAND_DISPLAY` et si `xvfb-run` est dans le `PATH`, `xvfb-run -a` est utilisé. `--studio-bin` complète `BAMBU_STUDIO_BIN`. L'installateur extrait l'AppImage une fois (`--appimage-extract`) et pointe sur `squashfs-root/AppRun`, où `Binary.ProfilesDir` trouve `resources/profiles/BBL`.

## Pont Claude Desktop

`bambu-mcp --api-token-file F` (ou `BAMBU_API_TOKEN_FILE`) : première ligne du fichier, BOM et CRLF tolérés (PowerShell 5.1), jamais journalisé ; `--api-token` l'emporte s'il est donné.

## Livraison et installation

Voir `scripts/release.sh|ps1` (artefacts nommés `<outil>-<os>-<arch>`, `SHA256SUMS` au format `sha256sum`), `deploy/linux/install.sh` (idempotent, fusion de `/etc/atelier/atelier.env`, jeton généré une fois, unité systemd durcie, timer de sauvegarde, `atelier-admin`), `deploy/linux/uninstall.sh` (ne supprime jamais données, sauvegardes, configuration, utilisateur ; garde-fou `safe_rm`), `deploy/windows/*.ps1`.

Points non éprouvés : exécution sous un vrai systemd (durcissement `ProtectSystem=strict` + `ReadWritePaths` ; `uv run` écrit dans `/opt/atelier/cad` et `HOME`), Bambu Studio AppImage sous `xvfb-run` sur le serveur, `install-agent.ps1` (tâche planifiée) sur un vrai poste.
