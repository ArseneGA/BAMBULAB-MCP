# Jalon 2 — catalogue (import, modèles, versions, opérations, aperçus)

Date : 2026-11-06. Périmètre : `internal/catalog` (nouveau), outils MCP du catalogue (`internal/mcpserver/catalog_tools.go`), API HTTP (`internal/httpapi/catalog.go`), migration `0020_catalog.sql`, commande `bambud seed-demo`. Dossier : §14.2, §15.4, §6.

## Principes tenus

- **Non destructif** : les originaux ne sont jamais déplacés, renommés ni modifiés (testé : empreinte des originaux comparée avant/après). Copie dans `data/blobs` (adressage par contenu), vérification d'empreinte après copie (`Blobs.Verify`), détection d'un fichier modifié pendant la lecture.
- **Dérivés séparés** : GLB, STL/3MF issus d'un STEP sont des blobs dérivés (table `derived_assets`), jamais à la place de l'original ; le GLB n'est servi que s'il est enregistré comme aperçu (jamais un original).
- **Racines autorisées** : `Config.ImportRoots` (flag `--import-root`, env `BAMBU_IMPORT_ROOTS`, liste séparée par `;` sous Windows / `:` sous Linux). Sans racine, tout import/scan est refusé. Chemin absolu obligatoire, liens symboliques résolus avant contrôle, traversée `..` neutralisée, lien sortant d'une racine refusé.
- **Audit** : chaque mutation écrit son entrée dans la même transaction (acteur `import`, `ops`, `mcp`, `derive`).

## Modèle de données (migration 0020)

Colonnes ajoutées : `models.description/license/provenance(JSON)`, `source_files.rel_path/origin_mtime_ns/unit`. Tables : `derived_assets(source_sha, kind, state, blob_sha, doc)` (kinds `analysis`, `preview_glb`, `step_stl`, `step_3mf` ; états `ok | pending | error | backend_missing`), `import_index(origin_path, taille, mtime, sha256, source_file_id, copied)` (import incrémental), `op_previews(token_hash, plan, expires_at, used_at)` (aperçus d'opérations). Les versions restent immuables (déclencheurs J1).

Modèle : collection (arborescente) > modèle logique > fichier source (empreinte, disponibilité `linux | windows_only`, chemin relatif, mtime d'origine, unité confirmée) > version immuable (parent, note, fichiers). Provenance et licence au niveau modèle. Le « fichier courant » d'un modèle est celui de sa dernière version.

## Import (`import_files`, job `catalog.import`)

1. `scan_folder` : inventaire en lecture seule (nombre, taille, formats, extensions non supportées, nouveau / modifié / déjà importé d'après l'index, octets à copier, espace libre du volume de stockage, plus gros fichiers). Aucune copie, aucun modèle, aucun job (testé).
2. `import_files` valide les chemins **avant** de mettre le job en file, puis les revalide à l'exécution. Options : `copy` (faux = indexation seule, fichiers `windows_only`, sans blob ni aperçu), `on_duplicate` (`skip` par défaut | `keep`), `recursive`, `keep_structure` (sous-dossiers → collections imbriquées, dossier importé → collection racine), `collection`, `tags`, `license`, `source`, `unit`, `name`, `wait_seconds`.
3. **Incrémental** : même chemin + taille + mtime → `unchanged` sans relire le fichier ; mtime seul changé → `unchanged` (index rafraîchi) ; contenu changé → **nouvelle version** du même modèle (parent = version précédente) ; contenu déjà au catalogue sous un autre chemin → `duplicate` (non ré-importé, `duplicate_of` renvoyé) ; modèle en corbeille → signalé, jamais ressuscité en silence.
4. **Reprise** : le job est rejouable et idempotent (chaque fichier est commité seul). Testé : annulation en cours de route puis relance sans doublon ; crash simulé (job `running` orphelin) → `Recover` le remet en file → il se termine.
5. `windows_only` → copie plus tard : le fichier existant passe en `linux` (`upgraded`), sans doublon, et analyse + aperçu sont lancés.
6. Validation de format : magic 3MF (zip) et en-tête STEP vérifiés à l'import (`rejected`) ; STL/OBJ validés par l'analyse (un maillage vide donne `analysis.state = error` sans casser l'import). Limite de taille (2 Gio), 500 000 entrées parcourues max. Pas d'extraction d'archives (hors 3MF) : non implémenté.

## Dérivés

| Job | Rôle |
|---|---|
| `mesh.analyze` | lit le blob avec `internal/mesh`, stocke `ModelReport` (niveau « calculé »), met à jour `models.dimensions` ; unité confirmée (`mm|cm|m|inch`) appliquée aux STL/OBJ seulement |
| `mesh.preview` | GLB (`MaxTriangles` 200 000, décimation signalée) en blob dérivé ; `not_represented` liste ce que le viewer ne montre pas (extras 3MF, matériaux) |
| `cad.step_import` | classe `heavy` ; `uv run --project <worker> python -m bambu_geometry step_import` (stdin JSON, une ligne JSON sur stdout, arguments en tableau) ; STL + 3MF dérivés stockés, puis analyse et aperçu du STL dérivé enregistrés sous l'empreinte du STEP |

uv et le dossier du worker sont configurables (`--uv-path` / `BAMBU_UV_PATH`, `--geometry-dir` / `BAMBU_GEOMETRY_DIR`, défaut `workers/geometry`). Backend absent ou `step_backend_missing`/`cad_backend_missing` du worker → état explicite `backend_missing` (fiche modèle, aperçu, analyse), job `failed` avec le code `cad_backend_missing` ; l'original STEP est conservé. `get_capabilities` annonce `cad_worker` selon la présence de uv + projet.

## Outils MCP (14, schémas d'entrée et de sortie via `contracts.MustSchemaFor`)

`search_models`, `list_collection`, `get_model_details`, `scan_folder`, `import_files`, `import_model`, `analyze_geometry`, `get_preview_asset`, `tag_models`, `link_model_versions`, `find_exact_duplicates`, `preview_file_operations`, `apply_file_operations`, `restore_from_trash`.

- `preview_file_operations` (rename, rename_file, move — collection créée au besoin —, add_tags, remove_tags, set_license, delete) renvoie portée (modèles/fichiers), différences avant/après, collections à créer, avertissements et un **jeton** (256 bits, stocké haché, 15 min, usage unique). Rien n'est appliqué.
- `apply_file_operations(token)` : tout ou rien, refuse un jeton inconnu / expiré / déjà utilisé, refuse si un modèle visé a changé depuis l'aperçu (empreinte `updated_at`+nom), audit par changement. `delete` = corbeille (jamais de suppression définitive ni de blob supprimé) ; `restore_from_trash` ; la corbeille se liste avec `search_models only_trashed`.
- `link_model_versions` : intègre des modèles importés séparément comme versions successives d'un modèle cible (versions immuables chaînées par parent) ; les modèles intégrés vont en corbeille.
- `find_exact_duplicates` : groupes par sha256, ou contrôle ciblé par empreinte / chemin (calculé sans copier) ; ne supprime rien.
- `get_preview_asset` : référence + URL HTTP locale signée (HMAC-SHA256, clé `data/assets.key` 0600, expiration 1 h) vers `/api/assets/{sha}.glb` ; jamais de base64.
- `analyze_geometry` : analyse stockée ou recalculée (unité confirmée mémorisée sur le fichier), fabricabilité heuristique (surplombs, épaisseur, orientations) pour `p1s|p1p|x1c|a1|a1mini`, avertissements explicites (unité supposée, tessellation STEP, aucune certification mécanique).
- Annotations : lecture seule / non destructif / destructif posées ; `apply_file_operations` est marqué destructif (hôte : confirmation).

## API HTTP (web app)

`GET /api/models` (q, tag, collection, format, availability, trashed=include|only, sort, desc, limit, offset), `GET /api/models/{id}`, `GET /api/collections`, `GET /api/collections/{id}`, `GET /api/assets/{sha}.glb` (signature obligatoire, `ETag` fort, `Range`, `Content-Type: model/gltf-binary`, CORS ouvert car l'URL est une capacité signée), `POST /api/import` (202 + job, ou 200 avec `wait_seconds`), `POST /api/scan`, `POST /api/operations/preview|apply`, `GET /api/trash`, `POST /api/trash/restore`, `POST /api/tags`, `GET /api/duplicates`. Corps JSON limités à 4 Mio, champs inconnus refusés. Erreurs : 400 `invalid`, 403 `not_allowed`, 404 `not_found`, 409 `conflict`, 503 `backend_missing`.

## Données de démonstration

`bambud seed-demo [--data-dir] [--dir] [--no-cad] [--wait]` : génère 10 modèles (pince en C, équerre, bouchon, engrenage 16 dents, écrou hexagonal, boîtier percé, crochet, support en T, plaque double, cale) en STL via `internal/mesh`, dans `<data>/demo-src/{Mecanique,Rangement,Maison}`, les importe par le chemin normal sous la collection `Démo` (CC0-1.0, provenance « données de démonstration », étiquettes par pièce), crée une 2e version de la pince, attend analyses et aperçus, affiche un rapport JSON. Idempotent (testé). Sans `--no-cad`, tente les gabarits CadQuery (`clamp`, `bracket`, `box`) si uv + CadQuery sont disponibles, sinon l'indique (`cad_skipped`).

## Limites et points ouverts

- **Worker CAO réel non exécuté bout en bout** : uv présent, appel du protocole validé jusqu'à l'erreur structurée `cad_backend_missing` (extra `cad` non installé sur ce poste) ; le chemin STEP est testé avec un worker injecté. Test réel : `BAMBU_TEST_REAL_WORKER=1 go test ./internal/catalog -run RealWorker`.
- Migration numérotée **0020** (laisse la place aux autres jalons) ; si une autre branche ajoute des migrations de numéro inférieur, une base déjà migrée ne les appliquerait pas : renuméroter à la fusion.
- Recherche texte : sous-chaîne ASCII insensible à la casse (pas d'accents ni de classement par pertinence) ; pas d'index plein texte.
- Doublons : exacts uniquement ; similarité géométrique non implémentée (dossier : fonction ultérieure).
- Pas d'export groupé, pas d'extraction d'archives, pas de vignettes PNG (aperçu = GLB), pas de relecture périodique des dossiers (le scan/ré-import est à la demande).
- Les opérations ne renomment/déplacent que le catalogue : aucun fichier sur disque n'est touché (choix assumé, jamais d'écriture dans les dossiers d'origine).
- L'analyse inline d'`analyze_geometry` (recalcul, fabricabilité) s'exécute dans la requête : sur un maillage de plusieurs millions de triangles elle peut prendre du temps.
- Mode `--embedded` du pont stdio : les URL d'aperçu pointent vers `bambud` qui doit tourner pour les servir.
- Authentification : inchangée depuis J1 (écoute locale uniquement). Les URL d'aperçu sont signées, le reste de l'API ne l'est pas.
- `-race` non exécuté (pas de compilateur C sur ce poste).
- Migration de fin de ligne : fichiers en LF (règle du dépôt).
