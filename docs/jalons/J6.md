# J6 (Go) — objectifs, candidats bornés, expériences

Paquet `internal/goals` ; outils MCP dans `internal/mcpserver/goal_tools.go` (`AddGoalTools(server, service)`, à brancher dans le serveur principal) ; migration `0110_goals.sql` ; ajout `slicer.ResolveWithOverrides` (valide des surcharges sans lancer Studio).

## Principe

Le texte libre n'est pas interprété par du code : Claude extrait des critères structurés (catalogue `list_goal_criteria`), `set_manufacturing_goals` valide, garde le texte original, renvoie ambiguïtés (seulement celles qui changent le choix), conflits avec compromis, critères non évaluables. Critère inconnu = `custom`, non évaluable, signalé. Aucun gagnant, aucun score global.

## Outils MCP

`list_goal_criteria`, `set_manufacturing_goals`, `modify_slicing_profile`, `create_experiment`, `compare_variants`, `apply_variant`, `record_print_result`, `get_print_memory`.

## Règles (`internal/goals/data/rules.json`, version 2026.11.1)

12 critères : aspect de surface, résistance (direction d'effort obligatoire ; évaluable par calcul de poutre si `params.engineering`), précision, souplesse, tenue thermique / extérieure / chimique (aucun levier : propriété du matériau), planéité, vitesse (`print_time_s`), économie de matière (`filament_g`), peu de supports (`support_g`), transparence/diffusion (mode obligatoire). Chaque levier : clé réelle de profil BBL, opération (set/add/scale), bornes, familles de matériaux validées, condition sur paramètre, effet, compromis. Les clés sont contrôlées contre les profils BBL réels (test) ; les énumérations (seam_position=back, ironing_type=top, draft_shield=enabled, gyroid) sont contrôlées contre `project_settings.config` de l'archive produite par Studio (test réel). Pas de levier brim : `brim_type` est absent des profils.

Matériau : famille lue dans `filament_type` du profil de base ; un objectif PETG avec un filament PLA est refusé ; famille inconnue ⇒ seuls les leviers `families:["*"]` ; les bornes de température viennent du profil filament lui-même.

## Générateur

Référence + N variantes (défaut 3, plafond 6 configurable, ≤ 3 facteurs par variante). Un critère : variantes graduées léger/modéré/marqué. Plusieurs critères : une variante par priorité + un compromis (un levier de chaque critère à tour de rôle ; réglage opposé ⇒ valeur intermédiaire ; leviers qui s'annulent ⇒ retirés et remplacés). Orientation via `internal/mesh` (effort dans le plan, contact maximal, surplombs minimaux). Chaque changement porte critère, levier, avant/après, effet, compromis attendu.

## Expérience

`create_experiment` fige version du modèle (refus si `expected_model_revision` périmée), fichier source (sha256), base (noms + empreintes des profils, revérifiées à la découpe) et met un travail `goals.slice_candidate` (classe heavy) par candidat. Mesures étiquetées : « estimation slicer » (temps, g, m, couches), « lecture du G-code » (supports, hauteur), « mesure géométrique » ; calculs « engineering » (facteur de sécurité selon l'orientation). `compare_variants` : tableau, seuils, classements par critère mesurable uniquement, liste « à vérifier par essai » avec l'essai suggéré.

`apply_variant(expected_revision)` : refus (`ErrStale`, avec la révision courante) si la révision attendue n'est pas celle figée, ou si le modèle a une version plus récente. `modify_slicing_profile(base_revision)` : refus si la base a déjà été prolongée (sauf `allow_branch`) ; renvoie profil process/filament complet, provenance, différence.

`record_print_result` : lie expérience/candidat, réglages prévus et écarts réels, photos (sha256 de blobs existants), mesures, observations ; mémoire réutilisée seulement pour même famille + même machine et (même modèle ou géométrie ±25 %), avec niveau de comparabilité (même filament ou non).

## Exemple réel (cube 20 mm, P1S, PLA Basic, « solide mais rapide » + aspect)

| Candidat | Temps | Matière | Couches | Changements |
|---|---|---|---|---|
| Référence | 542 s | 3,75 g | 100 | — |
| Priorité résistance | 667 s | 5,55 g | 100 | wall_loops 2→4, infill 15→30 %, gyroid |
| Priorité vitesse | 403 s | 2,96 g | 72 | layer_height 0,2→0,28, infill 15→5 %, top_shell 5→4 |
| Compromis | 558 s | 5,00 g | 100 | wall_loops 2→4, seam back, infill 17,5 % |

Classement par temps (estimation slicer) seulement ; facteur de sécurité (calcul) identique, car le calcul ne modélise ni parois ni remplissage.

## Limites

- Pas, ou peu, de recommandations fabricant citées : pas et bornes sont des heuristiques à valider par essai (sources à documenter).
- Réglages globaux seulement ; les zones sont notées et signalées, pas de variante par zone.
- Le facteur de sécurité ne dépend que de l'orientation. `BeamStress` peut refuser certains cas (TPU, flèche) : l'erreur est reportée dans l'entrée d'ingénierie.
- `support_g` est un ordre de grandeur lu dans le G-code (extrusion relative, densité du profil).
- Orientation : heuristique `internal/mesh`, appliquée au maillage STL de la découpe ; elle n'est pas écrite dans les versions de modèle (immuables), seulement dans la révision de profil appliquée.
- Seuls STL/OBJ/3MF découpables ; STEP refusé.
- Profil machine de `modify_slicing_profile` : clés modifiées seulement.
- Mémoire : pas d'oubli ni de pondération ; limitée à 500 essais par contexte.
- `AddGoalTools` n'est pas branché dans `mcpserver.New` (fichiers partagés) : créer `goals.New(Config{Store, Blobs, Queue, Registry, Slicer})` puis `mcpserver.AddGoalTools`.
