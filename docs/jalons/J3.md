# Jalon 3 : web app branchée et vues MCP App

Date : 2026-11-06. Périmètre : `web/` (nouveau : application React/Vite et bundle MCP App), `internal/webui/` (embed + repli SPA), `internal/mcpserver/app_views.go` (ressources `ui://bambu/*`, outil `get_mesh_chunk`). Dossier : §2, §14.3 ; recherche : `docs/research/mcp-apps.md`.

## Ce qui marche (vérifié sur un vrai bambud, catalogue `seed-demo`)

**Web app (`/`, servie par bambud, repli SPA)**

- Bibliothèque : `GET /api/models` (recherche texte, étiquettes, collection, format, disponibilité, tri, pagination 24 par page, filtres dans l'URL), arbre de collections (`/api/collections`), liste ou grille, sélection multiple et opérations groupées.
- Import : inventaire en lecture seule (`POST /api/scan`), puis import (`POST /api/import`, suivi du travail par `GET /api/jobs/{id}` avec barre, journal, annulation), options (collection, copie ou indexation seule, doublons, étiquettes, licence). Refus clair hors racine autorisée ou sans racine.
- Fiche modèle : dimensions, analyse géométrique réelle (niveau « calculé », unité supposée signalée), fichiers (empreinte, disponibilité), versions immuables, provenance, licence, journal d'audit ; viewer 3D qui charge le vrai GLB par l'URL signée (`GLTFLoader` de three, remise en Z haut et en mm, posé sur le plateau 256 mm, vues Iso/Face/Dessus/Côté/Plateau, sélection d'une sous-partie = un nœud du GLB, thème clair/sombre suivi). URL signée expirée : redemande automatique de la fiche.
- Opérations : renommer, déplacer, étiquettes, licence, corbeille, toujours « aperçu puis application » (jeton à usage unique de `/api/operations/preview`, tableau avant/après, avertissements, expiration ; jeton périmé ou état modifié : message et relance de l'aperçu).
- Corbeille (restauration) et doublons exacts (lecture seule).
- États : chargement, vide (catalogue vide, filtre sans résultat), erreur, **bambud injoignable** (bandeau et blocs d'erreur avec « Réessayer », sonde `/health` toutes les 10 s), **agent Windows hors ligne** (pastille issue de `/api/capabilities`, fichiers `windows_only` signalés), **backend CAO absent** (pastille, fiche et aperçu STEP avec explication), aperçu en cours de calcul (relecture automatique), aperçu en erreur, WebGL absent.
- Parcours fonctionnel automatisé : `web/scripts/e2e.mjs` (import avec inventaire sans effet de bord, aperçu puis application d'une étiquette, corbeille puis restauration) : OK.

**Build et embarquement**

- `web/scripts/embed.mjs` construit les deux bundles puis copie `web/dist` vers `internal/webui/assets/` et le HTML unique de la vue vers `internal/mcpserver/ui/views/`. Cibles : `scripts/build.ps1 -Task web|release`, `scripts/build.sh web|release`, `make web|release` (`release` = web, vet, tests, binaires).
- Sans build, `go build` et bambud fonctionnent : `/` répond une page « interface non construite » (503), `/api` et `/mcp` restent intacts ; `/api/*` inconnu répond en JSON 404 (jamais du HTML).
- Les artefacts construits ne sont pas versionnés (`.gitignore`, dossiers gardés par `.gitkeep`) : exécuter `scripts/build.ps1 -Task release` avant de livrer un binaire.

**Vues MCP App**

- Deux ressources `ui://bambu/search.html` (liée à `search_models`) et `ui://bambu/model.html` (liée à `get_model_details`) via `_meta.ui.resourceUri` (et la clé plate historique), MIME `text/html;profile=mcp-app`, `_meta.ui.csp = {}` (aucune origine externe : Three.js est dans le HTML, `callServerTool` pour toute I/O), `prefersBorder`. Un seul bundle monofichier (~1 Mio, `vite-plugin-singlefile`) sert les deux URI ; la vue choisit l'écran d'après la forme du résultat.
- Vue : résultats (clic = `get_model_details` par `callServerTool` puis fiche), fiche compacte avec viewer 3D, dimensions, sous-parties. Thème de l'hôte (`hostContext.theme`, `onhostcontextchanged`). `connect()` est appelé après la pose de `ontoolresult`.
- **`get_mesh_chunk`** (`visibility:["app"]`, lecture seule) : GLB d'aperçu en base64 par tranches de 72 000 octets, soit 96 000 caractères (< 100 000), `chunk_count`, `size_bytes`, `sha256` ; refus au-delà de 16 Mio ; la vue charge 4 tranches en parallèle et vérifie la taille recomposée. Pas d'URL HTTP.
- Sélection d'une sous-partie : `app.updateModelContext({content:[{type:'text',...}]})` avec modèle, version, fichier, sous-partie et dimensions ; envoyé aussi à l'ouverture d'un modèle (sans sous-partie). Le modèle de langage le voit au tour suivant, sans réponse immédiate.
- Repli : le texte de chaque outil reste dans `content` (hôte sans UI, Claude Code) ; la vue affiche aussi un message explicite hors hôte, aperçu absent ou erreur d'outil.
- Harnais `web/mcp-app/dev-host.html` : vrai client MCP vers `/mcp`, vraie ressource lue et contrôlée (MIME), iframe `sandbox="allow-scripts allow-same-origin"`, `AppBridge` de `@modelcontextprotocol/ext-apps` (initialisation, `tool-result`, proxy des `tools/call`, `ui/update-model-context` journalisé, bascule de thème). Lancer : `cd web && npx vite --config mcp-app/vite.config.ts` puis `http://localhost:5175/dev-host.html` (bambud sur 7878 ; `BAMBU_URL` pour un autre).

**Tests Go** : `internal/mcpserver/app_views_test.go` (ressources : liste, lecture, MIME, CSP sans domaine, absence de ressource externe dans le bundle ; liens outil-vue et `visibility`; `get_mesh_chunk` de bout en bout : tranches ≤ 100 000 caractères, GLB recomposé identique, erreurs) ; `internal/webui/webui_test.go` (repli, SPA, 404 des scripts, `/api` jamais masqué, méthodes). Les comptes d'outils et de ressources des tests existants deviennent des minima.

```json
      "args": ["--url", "http://127.0.0.1:7878/mcp"],
      "env": { "BAMBU_LOG_LEVEL": "info" }

  }

```

   (Pont stdio vers bambud lancé à part ; sans bambud séparé : `"args": ["--embedded", "--data-dir", "C:\\...\\data"]` avec `BAMBU_IMPORT_ROOTS` dans `env`, mais les URL d'aperçu exigent alors bambud ; la vue MCP App n'en a pas besoin.)

Demander : « Cherche mes modèles de pince » (vue résultats), cliquer un modèle (fiche et viewer), faire tourner, sélectionner une sous-partie, puis demander « quelle pièce ai-je sélectionnée ? » pour vérifier le contexte. ## Limites

- Pas de vignettes d'aperçu dans la liste (le GLB serait un contexte WebGL par ligne) : pastille de format.
- Les étiquettes proposées en filtre viennent de la page courante (pas d'endpoint des étiquettes).
- Authentification : inchangée (écoute locale, aucune). L'URL d'aperçu du web est relative à l'origine courante.
- Le viewer ne montre pas les extras 3MF ni les matériaux (le GLB ne les porte pas) ; mesure et coupe absentes.
- La vue MCP App n'est pas thémée par `styles.variables` de l'hôte (seulement clair/sombre) et n'utilise pas de police web (aucune origine externe autorisée).
- Pas d'édition (renommage, etc.) depuis la vue MCP App : lecture et sélection seulement.
- Un STEP sans backend CAO n'a ni aperçu ni sous-parties (`backend_missing` affiché).
- Navigateur de test : Chromium (Edge) via Playwright ; `go test -race` non exécuté.
- Le moteur Three.js est dupliqué dans trois chunks (web, prototype r3f des écrans « bientôt », vue MCP App) ; à unifier quand ces écrans seront branchés.
- Taille du bundle de la vue MCP App : ~1 Mio.
